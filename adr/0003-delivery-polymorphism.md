# ADR-0003. oneOf и discriminator для типов доставки

## Контекст

Метод `GET /partners` возвращает список магазинов-партнёров. У партнёров два типа доставки, и они описываются разными наборами полей:

- `slot` — `slot_from`, `slot_to` (даты);
- `express` — `duration_min_minutes`, `duration_max_minutes` (числа).

Пересечения между наборами нет. Нужно выразить в схеме данных, что объект `delivery` — это либо одно, либо другое.

## Варианты

**Вариант 1. Плоская схема: один объект, все четыре поля необязательные.**

Схема разрешает бессмысленные комбинации — например, `delivery_type: slot` вместе с `duration_min_minutes`, или объект вообще без полей. Валидация по схеме такие случаи не запрещает, и проверять корректность придётся вручную в коде клиента.

**Вариант 2. `oneOf` без `discriminator`.**

Перечислены два варианта схемы, но не указано, по какому полю их различать. Валидация работает, однако клиент вынужден определять тип перебором схем, а генераторы кода создают один объединённый тип вместо двух — разбираться, что именно пришло, приходится в коде.

**Вариант 3. `oneOf` + `discriminator` по `delivery_type`.**

Валидацию обеспечивает `oneOf`, а `discriminator` добавляет однозначность разбора: тип определяется по значению `delivery_type`, без перебора. Поле `delivery_type` входит в `required` обеих схем — без этого дискриминатор не работает.

**Вариант 4. Два отдельных необязательных поля: `slot_delivery` и `express_delivery`.**

Схема не запрещает заполнить оба поля или ни одного.

## Решение

Выбран вариант 3: `oneOf` + `discriminator` по `delivery_type`.

`mapping` задан явно и в этом случае обязателен: значения `slot` и `express` не совпадают с именами схем `SlotDelivery` и `ExpressDelivery`. По умолчанию инструмент ищет схему с именем, равным значению дискриминатора, — то есть искал бы `slot` и не нашёл бы её.

## Последствия

**Плюсы:**

- Невалидные комбинации полей отклоняются на уровне схемы.
- Клиенту не нужно определять тип перебором; генераторы кода создают два отдельных типа.
- Добавление третьего типа доставки — это новая схема и одна строка в `mapping`, без изменения существующих.

**Минусы:**

- Поддержка `oneOf` и особенно `discriminator` в инструментах неровная: некоторые генераторы клиентов обрабатывают их плохо или игнорируют `mapping`.
- Схема сложнее для чтения человеком, не знакомым с `oneOf`.
